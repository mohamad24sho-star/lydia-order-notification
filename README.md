# Lydia — نظام متابعة الطلبات والتنبيهات

مشروع ويب باللغة العربية يضم صفحة للزبون ولوحة للمطعم، مع تحديث حالة الطلب لحظيًا، ورسالة جاهزية على الشاشة مع رنين واهتزاز عندما تكون الصفحة مفتوحة، وإشعارات Web Push للمتصفحات والأجهزة المدعومة بعد تفعيلها.

## ما الذي يتضمنه؟

- **صفحة الزبون**: `http://localhost:3000/` — يدخل الزبون رقم الطلب أو يصل عبر QR.
- **لوحة المطعم**: `http://localhost:3000/admin` — إنشاء الطلبات، طباعة/تنزيل QR، وتغيير الحالة.
- **تحديث لحظي** عبر Socket.IO طالما الصفحة مفتوحة ومتصلّة بالإنترنت.
- **رنين واهتزاز** داخل الصفحة؛ على المتصفح السماح بتشغيل الصوت من تفاعل المستخدم، والاهتزاز يعتمد على دعم الجهاز.
- **إشعارات الخلفية** عبر Web Push وService Worker، بعد السماح بالإشعارات والعمل على HTTPS.
- **ملف بيانات محلي** في `data/orders.json`.

## التشغيل محليًا

يتطلب Node.js 20 أو أحدث.

1. فك ضغط الحزمة وافتح Terminal داخل مجلد `lydia-project`.
2. ثبّت الحزم:
   ```bash
   npm install
   ```
3. أنشئ إعدادات سرية ومفاتيح الإشعارات:
   ```bash
   npm run setup
   ```
   سيظهر لك **رمز دخول المشرف** في الطرفية. احتفظ به.
4. شغّل الموقع:
   ```bash
   npm start
   ```
5. افتح `http://localhost:3000` للزبون أو `http://localhost:3000/admin` للمطعم.

لتطوير الملفات مع إعادة تشغيل الخادم تلقائيًا استخدم `npm run dev`.

## اختبار التنبيه

1. ادخل إلى لوحة المطعم `/admin` بالرمز الذي ظهر عند `npm run setup`.
2. أنشئ طلبًا جديدًا، ثم افتح رابط الزبون أو امسح QR من الهاتف.
3. في صفحة الزبون اضغط **تفعيل الرنين وإشعارات الخلفية** واسمح بالإشعارات.
4. من لوحة المطعم اضغط **الطلب جاهز**. ستصل حالة التحديث فورًا، وتظهر نافذة الجاهزية مع الرنين والاهتزاز على الصفحة النشطة، كما يُرسل إشعار المتصفح عندما تكون الصفحة بالخلفية وفق دعم النظام.

يمكنك تنزيل صورة QR PNG من بطاقة الطلب في لوحة المطعم.

## النشر على الإنترنت

يلزم نشر التطبيق على استضافة تدعم Node.js واتصالات WebSocket، وضبط HTTPS. مثال شائع: Render أو VPS. بعد النشر، اضبط متغيرات البيئة:

- `NODE_ENV=production`
- `BASE_URL=https://your-domain.example` — الرابط العام الكامل من دون `/` في النهاية.
- `ADMIN_PIN` — رمز مشرف قوي وفريد.
- `ADMIN_SESSION_SECRET` — سلسلة عشوائية طويلة وسرية.
- `VAPID_SUBJECT` — مثل `mailto:you@example.com`.
- `VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` — مفتاحا VAPID. لإنشائهما محليًا استخدم `npm run vapid` ثم انسخ القيم إلى إعدادات الاستضافة. يجب أن يبقى المفتاح الخاص سرّيًا.

ملف `render.yaml` مثال لإعداد خدمة Render، لكنه لا يستطيع تكوين الدومين أو حساب الاستضافة بدلًا عنك.

## تنبيهات وقيود مهمة

- إشعار النظام في الخلفية يعتمد على دعم المتصفح والجهاز؛ لا يمكن ضمان الصوت أو الاهتزاز في كل هاتف. غالبًا لا يُسمح بتشغيل صوت مخصص من صفحة ويب بعد إغلاقها بالكامل. إشعار Push يمكنه الظهور عند توافر الدعم والإذن.
- إشعارات Web Push تتطلب HTTPS على النشر العام. `localhost` مسموح عادةً للتطوير، لكن اختبار الإشعارات على هاتف آخر يحتاج عنوان HTTPS عام.
- بيانات الطلبات هنا محفوظة في ملف JSON محلي. للنشر التجاري متعدد النسخ أو التوسع، انقل البيانات إلى قاعدة بيانات مُدارة واستخدم قرصًا دائمًا (أو قاعدة بيانات) لأن بعض منصات الاستضافة تمسح ملفات النظام عند إعادة البناء.
- لوحة الإدارة محمية برمز دخول وجلسة موقعة وقيود أولية على محاولات الدخول. قبل الاستخدام التجاري، أضف إدارة مستخدمين، سجل تدقيق، نسخًا احتياطية، وقاعدة بيانات دائمة.
- رمز QR يؤدي إلى رابط الطلب العام؛ لا تضع فيه بيانات شخصية حساسة.

## ملفات المشروع

- `server.js` — API، الجلسات، تحديثات Socket.IO، QR، إرسال Web Push.
- `public/index.html` و`public/customer.js` — واجهة الزبون.
- `public/admin.html` و`public/admin.js` — لوحة المطعم.
- `public/styles.css` — التصميم المتجاوب RTL.
- `public/sw.js` — إشعارات الخلفية.
- `scripts/setup.js` — توليد إعدادات ومفاتيح أولية.
